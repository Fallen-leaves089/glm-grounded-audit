# 环境与能力探测

## 原则

- 只记录当前 ZCode 会话实际探测到的事实，不沿用上一次会话或其他宿主的假设。
- 先做只读探测，再做需要副作用、后台任务或联网的动作。
- 不预置平台避坑清单；环境差异通过探测、证据和记忆处理。
- 工具缺失、权限拒绝或输出不可解析时，标记未覆盖，不模拟结果。

## 必记字段

| 字段 | 说明 |
|---|---|
| ZCode 版本 | 从会话、CLI、安装元数据或用户陈述中确认；不确定就写未知 |
| 模型标识与版本 | 只记录可观察到的模型名、路由和推理强度 |
| 工作目录 | `Bash` 会话 cwd；不要假定可以逐次覆盖 |
| 目标路径 | 用户给出的真实绝对路径；记录是否可读 |
| 运行模式 | `plan`、`build`、`edit`、`yolo`、`guarded` 或未知 |
| 操作系统与架构 | 当前进程实际报告的系统与架构 |
| shell 与版本 | ZCode 当前 Bash adapter 实际使用的 shell |
| 解释器 | Python、Node、Java 等的实际路径和版本 |
| Git | 版本、仓库根、当前分支、工作区状态 |
| 构建工具 | 实际可用的构建、测试、包管理工具及版本 |
| 容器/虚拟化 | 运行时是否可用、实际架构、权限 |
| 网络 | 是否可联网、是否被代理或策略限制 |
| 写权限 | 工作区、临时目录、报告目录、外部记忆目录 |
| 技能发现 | `zcode skills list --cwd <abs> --json` 的实际结果 |
| 工具面 | `Read`、`Glob`、`Grep`、`Bash`、`Skill`、`Agent`、`WebSearch`、`WebFetch` 等是否注册 |
| 后台任务 | `Bash` 的 `run_in_background` 是否可用；输出文件如何读取 |
| 子代理 | `Agent` / `Task` 是否可用；实际子代理类型和只读状态 |

## 能力状态

每项能力只使用以下状态：

- `present`：已实际调用或确认可用；
- `partial`：存在但版本、权限、参数或工具面受限；
- `absent`：确认不可用；
- `unknown`：无法确认，必须标未覆盖。

状态不是布尔值，不能把 `unknown` 写成 `present`。

## ZCode 专项探测

1. 确认目标路径真实存在且可读。
2. 用 `zcode skills list --cwd <absolute-project-path> --json` 和 `zcode commands list` 确认技能与命令是否真的被发现。
3. 记录运行模式；非交互任务必须显式传 `--mode`。
4. 确认 `Read` 可用；如果 direct `Glob` / `Grep` 被 embedded search 隐藏，不要伪造可用性。
5. 需要命令时，先记录 `Bash` 实际 cwd、shell 和输出/错误格式；不要假定可传自定义 cwd。
6. 需要长任务时，确认 `run_in_background` 返回的 ID、输出文件和完成通知如何读取。
7. 确认技能根和外部记忆目录是否可写；不要在技能根内创建本地记忆。
8. 检查项目 Hook 的信任状态；未信任的 Hook 不会自动执行。
9. 不读取或输出 ZCode 凭据、令牌、session 数据库和密钥文件。

## 失败与降级

- 目标不在可见工作区：停止并说明需要用户提供可读路径或只读副本。
- `Read` 输出被截断：继续分段读取或标记未覆盖，不能根据截断内容下结论。
- `Glob` / `Grep` 不可用：改用只读 `Bash` 搜索；若也不能保证只读，标未覆盖。
- `Bash` 超时或转后台：读取输出文件到终态；无法读取则标未覆盖。
- 权限拒绝：记录工具、模式和拒绝信息，不把进程 `0` 当成成功。
- 写权限不确定：不要写报告或记忆，先确认位置。
- 子代理不可用：顺序完成双轴审查，不模拟并行结果。
